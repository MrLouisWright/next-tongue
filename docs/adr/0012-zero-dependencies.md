# 0012. Zero dependencies beyond `next` and `react`

- Status: Accepted
- Date: 2026-10-14

## Context
i18n libraries often pull in parsers, file watchers, CLI frameworks and locale matchers. Each one adds supply-chain risk, install weight and upgrade work for a solo maintainer.

## Decision
- The published `next-tongue` package has **no `dependencies`** and no optional or bundled dependencies. Its only `peerDependencies` are `next` and `react`. This covers runtime, build-time codegen, the call-site loader and the CLI.
- Only Node built-ins and web platform APIs are used:
  - CLI: `util.parseArgs`, `readline`, `fs`, `path`, `child_process` only where needed, and global `fetch` for `tongue translate`;
  - dev watcher: `fs.watch`, not chokidar;
  - ICU: own parser ([ADR 0010](0010-own-icu-parser.md)); plurals and formatting via built-in `Intl`;
  - locale negotiation: precomputed tables generated by codegen, no locale-matcher package;
  - call-site loader: a small purpose-built scanner for `useT`/`t()` call sites, no Babel, SWC or oxc.
- devDependencies of the repo (test runners, linters) are allowed but never appear in the published package's dependency fields.
- **CI dependency budget check:** a CI job reads the published `package.json` (and `npm pack --dry-run` output) and fails if `dependencies`, `optionalDependencies` or `bundleDependencies` are non-empty, or if `peerDependencies` contains anything besides `next` and `react` ([#28](https://github.com/MrLouisWright/next-tongue/issues/28)).

## Consequences
- \+ `npm install next-tongue` installs nothing else; minimal supply-chain surface.
- − More code to own (parser, scanner, watcher, arg parsing).
- − Some conveniences (rich CLI prompts, robust cross-platform watching) are simpler than in mature libraries; documented limits apply.

## Alternatives considered
Allowing a few small, well-known dependencies (FormatJS parser, chokidar, a CLI framework): rejected by the maintainer.
